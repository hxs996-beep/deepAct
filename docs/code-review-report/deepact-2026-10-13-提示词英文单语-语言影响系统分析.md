### 对本次提问的两个直接回答

**Q1：模型可见提示词全部改成英文，是否合适？——方向合适，但有 1 处提示词陈旧陈述与 1 处范围口径缺口。**

- 合适的一面（已核实）：单一提示词源消除了 zh/en 双份漂移；语言包只剩单份、工具 schema 本就英文；与外部参照（claude-code / codex / deepseek-harness）一致——模型提示词单语，本地化落到 UI 文案表；提示词内容与「按用户语言回复」并不冲突。
- 不合适/需修的一面：`context/promptset/en/system.md:95` 逐字翻译了「会话语言从用户第一条消息锁定」，但**锁定机制本次已删除**（`context/langdetect.go:106`、`engine/loop.go:1004` 仅留「已删除」注释，生产代码零残留），提示词现在描述了一个不存在的引擎机制；此外 `tools/builtin/remember_preference.go:23` 的旧中文标题常量、`engine/loop.go:739` 的 `输入你的意见` 是 PRD 显式豁免项（前者不进提示词，后者只进 UI 选项）。

**Q2：是否破坏「按用户的语言回复」？——规则未被破坏，但语言「锁定」从引擎语义退化为纯模型自律。**

- 规则**等价保留**：`context/promptset/en/system.md:95` 与旧 `zh/system.md:95` 的「用用户的语言回复。会话语言从用户第一条消息锁定……」逐字对应，属忠实翻译；全仓「输出语言」类指令仅此一处（技能文档 `collab/ratd` 另有「用用户语言写 goal」一条）。
- 旧机制从未在代码层强制输出语言：父提交的 `UserLanguage` 家族只用于**选择提示词变体**（`pickPrompt(zh, en, zhPrompt)`），没有任何输出语言校验或纠正逻辑。因此「按用户语言回复」从来是提示词级约定，本次没有功能性的保证被移除。
- 真实变化是**语境 priming 方向反转**：中文会话里原本的中文 system prompt、中文 Block S、中文语言包、中文 nudge 全部变为英文，唯一语言锚点是 system.md:95 那一句英文指令（加用户自己的中文消息）。这是 claude-code / codex 的既有模式，可接受；但 `system.md:95` 后半句现在成了**不实陈述**（说「已锁定」，实际无引擎锁定），应改为行为化表述。
- 子代理不是缺口（已实测驳回一条误判）：`context/promptset/en/sub_agent.md` 自身不含语言规则，但 `engine/sub_agent.go:1210-1217` 的 `stableSystemPrompt()` 会拼接 `prompts.System`，即子代理同样拿到 `Reply in the user's language`。
