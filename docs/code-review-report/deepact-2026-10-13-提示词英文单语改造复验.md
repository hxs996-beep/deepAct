## 代码审查结果

### ⚠️ Important

#### 1. `tools/builtin/read.go:35` 残留中英重复的模型可见文本

```go
unchangedReadHint = "File unchanged since your last read — its content is already in the conversation. " +
    "Do not re-read it; act on what you already have or read a different section. " +
    "文件自上次读取后未变更，内容已在对话中，请勿重读；请基于已有内容行动或读取其他部分。\n\n"
```

- **为什么是问题**：该常量作为前缀拼进 `read` 的**工具返回文本**，属模型可见内容；同一语义英文句与中文句并存，正是本次重构要消灭的「混态」。同文件 `fileUnchangedStub`、`lspHint` 已是单英文，此处是唯一例外。
- **归属**：本次变更**未触及**该文件（`git show HEAD:…` 确认该中文句在改动前已存在）→ 属「已有问题 + 本次未覆盖」，但直接反驳文档「生产代码中模型可见文本已无中文残留」的声称，是本次目标未达成的证据。
- **建议**：删除中文句，只保留英文（与同文件风格一致）。

#### 2. `tools/builtin/remember_preference.go:18` 中文小节标题出现在模型可见位置

```go
const preferenceSectionHeading = "## 用户偏好"
```

- **为什么是问题**：① 该常量拼进工具 `Description`（第 33 行 `...under the "## 用户偏好" section...`）→ 工具 schema 进 LLM 上下文，且该标题在我本次会话的系统提示词中确实可见；② 它同时是写入 AGENTS.md 的小节标题，而 AGENTS.md 被逐字注入稳定提示词（`context/agents.go`）。两处模型都能看到中文。
- **难点（需作者取舍）**：`upsertPreference` 按字面相等匹配 heading（`tools/builtin/remember_preference.go:106`）。若直接把标题改成英文，已存在的中文小节将不再被匹配，会在同一文件里分裂出两节。因此修复必须配套迁移（识别旧中文标题并原地改名），或**在文档中显式列为允许残留的例外**——不能笼统声称「模型可见文本已无中文残留」。
- **归属**：同属「已有问题 + 本次未覆盖」。

#### 3. `engine/approval.go:215` 危险命令确认框由中文变英文，与「不改 UI 文案」冲突【本次引入】

- **变更前**：`approvalAskMessage(zh bool, …)` 用 `pickPrompt(zh, en, zhPrompt)` 按会话语言输出，中文会话看到 `⚠ 危险命令: … [Y] 确认执行 [N] 取消…`。
- **变更后**：`approvalAskMessage(reason, cmd)` 单英文：`⚠ Dangerous command: … [Y] confirm [N] cancel…`。
- **为什么是问题**：该文案经 `TurnResult.Questions` → `EngineResponse.Questions` 交给 UI 渲染（`engine/turn.go:610`、`engine/loop.go:636`、`ui/model.go:1876-1880`），是**用户可见**文案。文档「不自洽点」第 49 行明确写「不改 UI 文案（`ui/`、`cmd/eval.go` 的报告是用户可见输出，CLI 界面语言为中文）」，但同一文档的改动清单第 42 行又把 `engine/approval.go` 列入——文档内部矛盾。实际效果是：中文用户的危险命令确认框正文变英文，而同屏选项仍是中文（`engine/loop.go:632` 的 `确认执行`/`取消`），出现中英混排。
- **建议**：二选一并同步文档——(A) 保留中文（把该 message 视为 UI 文案，恢复按 UI 语言输出）；(B) 明确接受「引擎内用户可见文案随提示词一起英文化」，并修正文档第 49 行的表述。

### ℹ️ Minor

#### 4. `skill/builtin/{collab,ratd}/SKILL.md` Caveats 首条新增了原文没有的半句

旧句「会话语言为中文时使用上面中文角色提示；英文时译为英文。」→ 新句 `Write the goal in the user's language; keep the tool calls themselves as described.`。替换掉过时规则是正确的（双语角色提示已删除），但新增的 `keep the tool calls themselves as described` 是原中文没有的约束——属范围外的轻微新增，方向与系统提示一致。
